# Implementation verification

Verified on the supplied Linux host with Node 22.11.0 and pnpm 9.15.9:

- `pnpm typecheck`: strict TypeScript passes for the CRM, shared models, Remotion composition, devnet CLI and browser-test configuration.
- `pnpm test`: the standard tests pass, covering wire privacy/crypto, enrollment idempotency, persistence, concurrent SQLite spend arbitration across separate processes, winning-operation replay after restart, hosted auth/origin guards, voice provider contracts and Anchor byte encoding. The opt-in Postgres test is skipped without `EDGECARE_TEST_DATABASE_URL`; it was also run separately against the provisioned Neon database and passed concurrency, persistence, expiry and cross-table consistency checks.
- `pnpm test:launcher`: thirteen tests pass, covering exact simulator selection, private voice configuration, Next.js environment parsing, stale-backend rejection and simulator credential isolation, including relaunching installed apps against the hosted URL and the native rebuild sequence. Actual Mac execution remains unverified from this Linux host.
- `pnpm build`: production CRM/API build passes, including conversation and profile-normalization routes.
- `pnpm schema`: generated referral schema is unchanged; Swift and TypeScript consume matching fixtures.
- Browser integration against a production server: login, filters, live enrollment arrival, shared spend propagation, retry acceptance/competing-spend rejection, privacy projection, stale-data display during a lost connection, reconnect and logout pass. Desktop/mobile screenshots are under ignored `artifacts/browser/`. Responsive filter and tablet logout regression checks are included.
- Independent Python HKDF/AES-GCM/SHA-256 verification matches all three bundled Swift/TypeScript fixture commitments.

Mocked voice tests verify omitted STT language hints, confidence handling, English profile transport, language-specific voices, mismatches, provider failures, consent gates and strict Runware function-call validation. The production API passed typed intake in English, Finnish, Somali, Arabic and Russian: each turn produced an English profile, a reply in the input language and nonempty ElevenLabs audio. A follow-up correction changed the English profile from two days to three days. English audio intake also passed automatic detection through the hosted route. Evidence is in `artifacts/hosted-verification.json`.

Three direct live probes and the hosted multilingual intake checks passed with that adapter.
