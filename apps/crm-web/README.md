# Doctor CRM and shared demo backend

Run from the repository root with `pnpm dev`; configure `apps/crm-web/.env.local` from `.env.example`. The server binds to loopback by default and stores referrals and registry state in SQLite at `.data/edgecare.sqlite`. It fails closed unless `DEMO_MODE=true`, `CHAIN=mock`, `LLM=ondevice`. This is not a production clinical service.

Open the browser to enter the CRM automatically, without a demo code or login. The demo role uses a signed, HTTP-only, SameSite=Strict cookie with an eight-hour expiry (Secure on HTTPS). A missing or expired session is re-created automatically; failed requests show a retry option. This demonstration workspace is public to anyone with its URL and is not verified clinical authentication. Use separate random `EDGECARE_CLINICIAN_TOKEN` and `EDGECARE_ISSUER_TOKEN` values for connected devices: clinician bearer authorizes list, detail, verification envelope, registry read and spend; issuer bearer authorizes enrollment, referral updates and registry create. Device tokens are not sent to the browser or required to open its session. Without configured tokens, only native requests to loopback may use these APIs without a browser session. Cross-origin requests are rejected, and session creation requires the explicit synthetic demo configuration. No real data is permitted.

The clinician workspace filters anonymous referrals by status, risk band, specialty, UTC dates and search, and sorts by newest or highest demo risk. The list/detail projection omits source, kiosk ID, salt, commitment hash and all ciphertext. Encrypted envelopes are only returned at the separate clinician verification endpoint. The browser never requests them. Registry status refreshes every two seconds while the browser is visible; interrupted connections retain the last received records with a visible warning.

The shared registry supports `GET/PUT /demo/commitments/:id` and `POST /demo/commitments/:id/spend`. PUT takes `{ commitment_hash }`; spend takes `{ commitment_hash, operation_id? }`. All IDs are canonical UUIDs. Native clients should durably persist a distinct UUID operation ID before a provisional spend, and reuse that ID on retries. The same winning operation/hash succeeds after response loss or restart; other spends return 409. A same-hash PUT remains idempotent after spend. The account response is always `{ commitment_hash, spent, created_slot, spent_slot }`; slots in this demo registry are millisecond logical timestamps, not Solana slots. Hash conflicts fail atomically in either enrollment/create order. Expired enrolled referrals cannot be spent. SQLite immediate transactions and a conditional update enforce first accepted spend wins. Local-only native mock stores do not share cross-device state; connected-demo devices must point to this one backend.

All referral responses disable caching. Mutation bodies are streamed with a 128 KiB bound and strict schemas reject identity, passcodes and plaintext signature fields. The workspace starts empty; fixture referrals load only when `EDGECARE_TEST_FIXTURES=true`, which the browser tests set. The fixture crypto wire format is unchanged. See the root API contract and architecture notes for the encryption protocol and its demo limitations.

Validation: `pnpm --filter @edgecare/crm-web typecheck`, `pnpm test`, `pnpm --filter @edgecare/crm-web build`. Tests cover enrollment idempotency, private projections, malformed and oversize input, authorizations, hash consistency, persistent state, expiry, single-use conflicts and replay after restart.

Streaming speech uses `EDGECARE_CLOUD_VOICE=true`, `EDGECARE_VOICE_ENGINE=gemini_live`, `GEMINI_API_KEY`, `GEMINI_LIVE_MODEL=gemini-3.8-live` and optional `GEMINI_LIVE_VOICE=Kore`. `GET /demo/voice/config` selects the transport; `POST /demo/voice/live/session` requires issuer authorization or a demo clinician session and explicit consent, then returns one-use constrained Google credentials (connect within one minute; five-minute maximum lifetime). Rebuilt native apps stream PCM directly to Google, receive native speech and validated English profile tool updates, and stop capture on completion or an explicit stop. The permanent key and provider errors never reach the client. See [Live intake](../../docs/voice-intake.md#gemini-live-streaming-speech).

The legacy voice service remains available through `EDGECARE_VOICE_ENGINE=legacy`, `GEMINI_API_KEY`/`GEMINI_MODEL` or Runware configuration, `ELEVENLABS_API_KEY`, and `ELEVENLABS_VOICE_ID`. `POST /demo/voice/turn` requires issuer authorization or a clinician demo session and explicit `consent:true`. It accepts exactly one `text` or `audio_base64` plus `audio_mime_type`, with optional language, previous English profile and bounded conversation history. Audio is limited to 6 MiB; JSON to 9 MiB. Scribe v2 detects language automatically because `language_code` is omitted; confidence below 0.65 asks the patient to retry. Gemini returns the next response in that language and updates canonical English profile fields. `POST /demo/profile/normalize` retains the text-only structured-form translation path and skips synthesis.

Responses include `transcript`, `detected_language`, `reply`, `profile`, nullable `audio_base64`/`audio_mime_type`, `speech_available`, and nullable `speech_error`. Default TTS is `eleven_v3`, which supports Somali, Finnish, Arabic, Ukrainian and English. Optional `ELEVENLABS_VOICE_ID_SO` and corresponding language overrides select a configured voice; no patient voice cloning occurs. Unsupported speech languages or TTS failures retain the successful text and English profile with an explicit speech-unavailable state. Disabled/missing providers return 503; malformed provider output returns 502. No live provider success is claimed by mocked tests.

This application does not write or log audio, transcripts, or conversation profiles on the voice route. Consent must disclose that ElevenLabs receives audio and response text, and Google receives transcript/context; provider processing and retention policies apply. `ELEVENLABS_ZERO_RETENTION=true` requests their optional enterprise-only zero-retention setting; it is not enabled by default or promised for ordinary accounts. Native mock/offline mode never invokes these endpoints. The local structured form remains available when providers or connectivity are unavailable.

Provider references: [ElevenLabs transcription](https://elevenlabs.io/docs/api-reference/speech-to-text/convert), [speech generation](https://elevenlabs.io/docs/api-reference/text-to-speech/convert), [model language support](https://elevenlabs.io/docs/overview/models), and [Gemini generation and structured output](https://ai.google.dev/api/generate-content).
